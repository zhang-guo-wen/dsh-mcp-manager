# @guowenzhang/dsh-mcp-manager

中文 | [English](<README.md>)

## 解决什么问题

DeepSeek Harness 添加 MCP 不够方便，配置多个 MCP 后默认全部加载工具，占用大量上下文。

本插件在设置页提供 MCP 新增、编辑与开关。使用按需加载时，初始上下文只保留 MCP 名称和描述，模型在运行过程中按需启用；同时支持工具过滤，只加载选中的部分工具。

插件列表的显示名称与介绍支持英文和中文，随 Harness 语言设置显示，英文为默认回退；英文名称为去掉 npm scope 的原包名，中文名称说明用途，安装仍使用不变的真实包名。

一页两个页签：「服务器」是名册，「设置」是加载方式与一次把多少工具内容交给模型。服务器列表独立滚动，上方页面标题、页签、新增按钮与筛选栏保持固定。Agent 预设名称与新建会话使用同一套宿主翻译，随界面语言更新；自定义名称保持原样。编辑器里配置、密钥与工具列表分为独立标签页；新增行的写入落点由弹窗里的「配置范围」**一个下拉**决定，选项就是全局与全部已声明预设；工具列表逐行标出该工具估算的 token 量，并汇总当前加载与取消勾选各是多少。开关失败会在该行内提示并可重试。

## 安装

需已安装 DeepSeek Harness、`pnpm`，并使用 Node.js ≥22.18 或 ≥24.2。

```sh
npx @deepseek-ai/dsh plugin --profile web add @guowenzhang/dsh-mcp-manager@^1.1.0
```

安装后重启宿主并刷新页面，打开 **设置 → MCP 管理**，新增 MCP 行并填写用途描述。这一页分两个页签：**服务器**（名册：一个列表，全局行在最前并带「全局」标签，下面是通过预设下拉选中的那个 Agent 预设的行；点卡片本身打开编辑器，编辑器分 **配置 / 密钥 / 工具列表** 三页——有环境变量或请求头的行直接落在密钥页）与 **设置**（**MCP 加载方式**：默认「动态插入」；下面是一次有多少工具内容进上下文）。新增时「配置范围」一个下拉就选好落点：全局，或某个 Agent 预设。新增表单里带 `*` 的两个字段（服务器名、JSON 配置）是必填；粘贴 JSON 后服务器名会按它自动填好（`npx -y @upstash/context7-mcp` → `context7`），你改过它之后就不再自动写。

其他安装方式与开发说明见 [AGENTS.md](https://github.com/zhang-guo-wen/dsh-mcp-manager/blob/master/AGENTS.md)。

## 进一步省上下文：检索、分页、只带名称

**设置 → MCP 管理 → 设置** 控制一次调用有多少工具内容进入上下文，加载方式也在这一页。MCP 规范本身没有给 `tools/list` 查询参数，也没有「只列名称」的形态；官方[客户端最佳实践](https://modelcontextprotocol.io/docs/2026-07-28/develop/clients/client-best-practices)把渐进式发现放在宿主侧，这一页做的就是这件事：

| 设置 | 作用 |
|---|---|
| **工具检索**（`search`） | 注册 `mcp_search`：模型用关键词在所有已发现的服务器里找工具，只拿到工具名和一行描述。 |
| **检索时索引未缓存的服务器**（`searchIndex`） | 允许检索为还没有工具目录的服务器临时连一次（最多同时 3 台、单台 8 秒）。默认关闭，保证检索是一次廉价读取。 |
| **每次列出条数**（`pageSize`） | `mcp_load` / `mcp_search` 一次最多列出这么多条，其余用 `nextCursor` 翻页。 |
| **只列名称与描述**（`namesOnly`） | `mcp_load` 默认不带参数 schema；按名字要某一个工具时仍会返回它的完整参数。 |
| **单台服务器最多拉取**（`maxTools`） | 给 `tools/list` 翻页设上限，超大服务器不会一次灌满请求。 |
| **列出工具注解**（`annotations`） | 把服务器声明的 `readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint` 带进列表。 |
| **隐藏破坏性工具**（`hideDestructive`） | 把 `destructiveHint` 明确为 true 的工具从会话可见集合中完全去掉。 |

「设置」页签还会显示工具目录缓存（服务器数、工具数、缓存时间），清空按钮同时清除内存与磁盘目录。所有开关都是活设置：保存后对下一次加载、检索或重建索引生效，不需要重启。

**工具目录数据库：** 全部 MCP（本地 `stdio` 与 HTTP/SSE/Streamable HTTP 服务器）统一保存到 `<DSH_HOME>/cache/dsh-mcp-manager/<profile哈希>/catalog.sqlite`。本地目录长期保留，不参与刷新按钮的连接操作；服务器声明 `ttlMs` 时，按它的有效期在下一次检索重新发现，未声明时保留到手动刷新。「工具目录缓存」标题下直接显示目录状态，「刷新」只重新连接当前启用的 HTTP/SSE 服务器，失败保留原目录并逐台提示；「清空缓存」清除全部目录。没有手动设置的缓存有效期。新增探测成功会立即保存工具目录，但**不保存 MCP 配置**，探测失败不影响直接保存。命令、参数、实际工作目录、环境、URL 或请求头变化后按配置摘要区分目录。数据库只保存公开工具定义与摘要，不保存原始配置或凭据；工具定义自身仍可能含服务器发布的敏感文本。实际调用工具仍需真实连接。

## 注意事项

- **按需加载覆盖两个平面，而且启动时一个进程都不起。** 「动态插入」（`dynamic`，默认）与「延迟加载」（`lazy`）下，允许的行在它的插件真正运行之前就被抑制，所以宿主启动与 Agent 预设重建都不会启动任何 MCP 进程；连接在第一次 `mcp_load` 时才建立。全局组合声明行同样跟随加载方式：「全部加载」（`eager`）下由组合直接挂载，「动态插入」「延迟加载」下保持被拦住的状态，直到 `mcp_load` 按需拉起并与其他会话共用同一条连接。工具过滤对全局行仍不生效。
- **按需加载，加载后复用。** 连接放在宿主级常驻池里，键是「行 + 连接配置」：同一台服务器再次加载——同一会话、别的会话、子代理——都复用同一条连接（stdio 就是同一个子进程）。`mcp_unload` 只释放调用方那个会话的引用；最后一个会话释放后服务器才停止，会话结束同样只释放引用。连接随宿主进程存活——提交不同的加载模式会重建工具面并释放该模式的引用，宿主重启后需要重新 `mcp_load`。「启动时不启动任何进程」与之前是否加载过无关。
- **动态插入（`dynamic`，默认）**把该服务器的工具加入加载它的那个会话，只注册你的过滤规则与本次加载请求留下的工具；**延迟加载（`lazy`）**通过固定代理调用工具，不改变工具列表。模型使用 `mcp_load` / `mcp_unload`，`mcp_load` 还支持 `query`（只加载命中的工具）、`tool`（只加载一个工具并取回它的参数）和 `cursor` / `limit`（长列表翻页）。
- **名册是一个列表，没有分组标题**：全局行恒在最前，并带「全局」标签；下面的行属于筛选栏里选中的那个 Agent 预设（预设下拉列出**全部已声明预设**，含还没有行的，同时决定新增时写到哪个预设）。改名册筛选不会隐藏任何平面——选中某个预设时全局行照样列出，因为会话本来就带着它们。编辑某一行则写回该行自己的平面。
- 工具过滤与优化开关在下一次加载时生效，已加载的 MCP 不会自动更新。加载或读取工具列表需要连接服务器，可能等待子进程启动。
- **按需加载的服务器不提供服务器 instructions 与资源工具**：它们的工具走同一个 harness 适配器、绑定质量一致，但提供 instructions 与共享资源的那条挂载路径已经没有了；需要这两样就把行放进 Agent 预设并选「全部加载」。
- **全局平面开箱即用：首次打开「MCP 管理」时自动创建。** 全新安装的 profile 只挂宿主自己的 root Include（每次启动会被重写），所以「全局」原本不可写。插件会在**每个宿主进程第一次读取名册时**自动创建一次：在 profile 目录新建 `mcp.cordis.yml`（空行清单），并向 `cordis.patch.yml` 追加一行 `cordis:include`（`initial: []`），随后重载让 Include 立刻挂载——不需要点任何按钮，也不碰宿主的 root Include 或其他配置。自动创建失败（或宿主较老）时，名册上方会显示原因与「启用全局（自动创建）」重试按钮；在新增弹窗里把「配置范围」切到「全局」也会触发同一次创建。写成功但没挂载时提示重启后生效。
- **全局行写在自己的 Include 文件里时，设置页能直接开关它。** 写入目标是**你自己的**那个 file-backed Include 的文件——宿主的 root anchor 被排除，所以"profile 自己声明了一个 Include"的组合不再被判成只读。由组合本身（或补丁层）声明的行在那个文件里没有对应行，因此**仍然只读**：开关与行内按钮置灰、卡片也不再打开编辑器，原因写在控件提示里，服务端也会以 `mcp/read-only` 拒绝写入；这类行照旧能按需加载、复用池、在「全部加载」下挂载。**一条已知限制**：全局写入是整表重写那个文件，文件里的注释与你自己的引号风格会丢，启用后还会留下显式的 `disabled: false`——功能正确，但不等于你写下的原文。
