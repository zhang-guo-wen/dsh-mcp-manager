# @guowenzhang/dsh-mcp-manager

中文 | [English](<README.md>)

## 解决什么问题

DeepSeek Harness 添加 MCP 不够方便，配置多个 MCP 后默认全部加载工具，占用大量上下文。

本插件在设置页提供 MCP 新增、编辑和 Claude Code 配置导入。使用按需加载时，初始上下文只保留 MCP 名称和描述，模型在运行过程中按需启用；同时支持工具过滤，只加载选中的部分工具。

插件列表的显示名称与介绍支持英文和中文，随 Harness 语言设置显示，英文为默认回退；英文名称为去掉 npm scope 的原包名，中文名称说明用途，安装仍使用不变的真实包名。

## 安装

需已安装 DeepSeek Harness、`pnpm`，并使用 Node.js ≥22.18 或 ≥24.2。

```sh
npx @deepseek-ai/dsh plugin --profile web add @guowenzhang/dsh-mcp-manager@^1.1.0
```

安装后重启宿主并刷新页面，打开 **设置 → MCP 管理**，新增或导入 MCP，填写用途描述。这一页分两个页签：**服务器**（名册，全局分组恒在最前，下面才是 Agent 行；默认使用「动态插入」；需要过滤工具时在 **编辑 → 工具列表** 中只保留所需工具）与 **上下文**（一次有多少工具内容进上下文）。新增或导入时，「配置范围」/「导入到」下拉决定写进全局平面还是某个 Agent 预设。

其他安装方式与开发说明见 [AGENTS.md](https://github.com/zhang-guo-wen/dsh-mcp-manager/blob/master/AGENTS.md)。

## 进一步省上下文：检索、分页、只带名称

**设置 → MCP 管理 → 上下文** 控制一次调用有多少工具内容进入上下文。MCP 规范本身没有给 `tools/list` 查询参数，也没有「只列名称」的形态；官方[客户端最佳实践](https://modelcontextprotocol.io/docs/2026-07-28/develop/clients/client-best-practices)把渐进式发现放在宿主侧，这一页做的就是这件事：

| 设置 | 作用 |
|---|---|
| **工具检索**（`search`） | 注册 `mcp_search`：模型用关键词在所有已发现的服务器里找工具，只拿到工具名和一行描述。 |
| **检索时索引未缓存的服务器**（`searchIndex`） | 允许检索为还没有工具目录的服务器临时连一次（最多同时 3 台、单台 8 秒）。默认关闭，保证检索是一次廉价读取。 |
| **每次列出条数**（`pageSize`） | `mcp_load` / `mcp_search` 一次最多列出这么多条，其余用 `nextCursor` 翻页。 |
| **只列名称与描述**（`namesOnly`） | `mcp_load` 默认不带参数 schema；按名字要某一个工具时仍会返回它的完整参数。 |
| **单台服务器最多拉取**（`maxTools`） | 给 `tools/list` 翻页设上限，超大服务器不会一次灌满请求。 |
| **缓存有效期**（`catalogTtlMs`） | 发现结果能在多久内直接回答检索而不重新连接。服务器给出的 `ttlMs` 更短时以服务器为准，`notifications/tools/list_changed` 立即让该服务器缓存失效。 |
| **列出工具注解**（`annotations`） | 把服务器声明的 `readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint` 带进列表。 |
| **隐藏破坏性工具**（`hideDestructive`） | 把 `destructiveHint` 明确为 true 的工具从会话可见集合中完全去掉。 |

「上下文」页签还会显示工具目录缓存（服务器数、工具数、缓存时间），并提供清空按钮。所有开关都是活设置：保存后对下一次加载、检索或重建索引生效，不需要重启。

## 注意事项

- **按需加载覆盖两个平面，而且启动时一个进程都不起。** 「动态插入」（`dynamic`，默认）与「延迟加载」（`lazy`）下，允许的行在它的插件真正运行之前就被抑制，所以宿主启动与 Agent 预设重建都不会启动任何 MCP 进程；连接在第一次 `mcp_load` 时才建立。全局组合声明行同样跟随加载方式：「全部加载」（`eager`）下由组合直接挂载，「动态插入」「延迟加载」下保持被拦住的状态，直到 `mcp_load` 按需拉起并与其他会话共用同一条连接。工具过滤对全局行仍不生效。
- **按需加载，加载后复用。** 连接放在宿主级常驻池里，键是「行 + 连接配置」：同一台服务器再次加载——同一会话、别的会话、子代理——都复用同一条连接（stdio 就是同一个子进程）。`mcp_unload` 只释放调用方那个会话的引用；最后一个会话释放后服务器才停止，会话结束同样只释放引用。连接随宿主进程存活——提交不同的加载模式会重建工具面并释放该模式的引用，宿主重启后需要重新 `mcp_load`。「启动时不启动任何进程」与之前是否加载过无关。
- **动态插入（`dynamic`，默认）**把该服务器的工具加入加载它的那个会话，只注册你的过滤规则与本次加载请求留下的工具；**延迟加载（`lazy`）**通过固定代理调用工具，不改变工具列表。模型使用 `mcp_load` / `mcp_unload`，`mcp_load` 还支持 `query`（只加载命中的工具）、`tool`（只加载一个工具并取回它的参数）和 `cursor` / `limit`（长列表翻页）。
- **名册是一个列表**：全局分组恒在最前（不会被预设下拉过滤掉），下面是 Agent 行。预设下拉收窄 Agent 行，列出**全部已声明预设**（含还没有行的），同时决定新增或导入时写到哪个预设；编辑某一行则写回该行自己的平面。
- 工具过滤与优化开关在下一次加载时生效，已加载的 MCP 不会自动更新。加载或读取工具列表需要连接服务器，可能等待子进程启动。
- 导入只读取 Claude Code 和项目 MCP 配置，不修改来源文件。**按需加载的服务器不提供服务器 instructions 与资源工具**：它们的工具走同一个 harness 适配器、绑定质量一致，但提供 instructions 与共享资源的那条挂载路径已经没有了；需要这两样就把行放进 Agent 预设并选「全部加载」。
- **全局行写在自己的 Include 文件里时，设置页能直接开关它。** 写入目标是**你自己的**那个 file-backed Include 的文件——宿主的 root anchor 被排除，所以"profile 自己声明了一个 Include"的组合不再被判成只读。由组合本身（或补丁层）声明的行在那个文件里没有对应行，因此**仍然只读**：开关与「编辑」置灰并给出原因，服务端也会以 `mcp/read-only` 拒绝写入；这类行照旧能按需加载、复用池、在「全部加载」下挂载。**一条已知限制**：全局写入是整表重写那个文件，文件里的注释与你自己的引号风格会丢，启用后还会留下显式的 `disabled: false`——功能正确，但不等于你写下的原文。
- **验证状态：** 行为有三层验证。`npm test` 通过 **21 个文件 / 237 项**，`npm run test:harness` 通过 **6 个文件 / 25 项**（`dynamic` 下 mcp-client 回调从不执行；全局行同样适用，含"本插件加载前就被组合挂载"的行；两个会话复用同一条连接、`mcp_unload` 每次只释放一个引用；写在自己 Include 文件里的全局行能在设置页开关，被用户停用的行开关立即显示为关；一份目录跨注册代次共享；超时未连上的连接会被关闭而不是泄漏进程；池的 claim 按次计数，同一服务器的并行加载收敛为一个视图；发布点被接管的 file-backed 行不改写它的文件）。隔离实例用当天的产物（`lib/index.mjs` `121B8C0A…`、`lib/client.js` `E1B1051A…`）+ `@deepseek-ai/dsh@0.2.0-rc.2` 实测——该版本就是 npm 上的 `latest`/`next`，也是你日常实例实际运行的宿主：`dynamic` 下启动后没有任何 MCP 进程（marker 文件从未创建、进程 0、stderr 为空），`eager` 对照四台长期存活，两个会话多次 `mcp_load` 复用同一条子进程。当天晚些时候的修复重建了产物（`lib/index.mjs` `53FD00C5…`、`lib/client.js` `9777E8E9…`），两套测试对新产物重跑全绿，但**没有做新的隔离实例实测——上面的读数描述的是较早那份产物**。更早产物（`9B5D8D19…`、`D498FEC7…`）的读数保留在验证记录里作为历史。较早的一次兼容性验证在 `0.2.1-alpha.1`（2026-10-07，针对 `livePresetMounts` 移除的适配）；该 `alpha` tag 现为 `0.2.1-alpha.4`，本次工作**未**在 alpha 线上复跑。未覆盖：真实 `npx -y` 冷启动耗时、GUI 里由模型决定的调用路径、`tools/list_changed` 跨会话重同步、活动实例内运行中切换加载模式、活动实例里的 `lazy` 池复用、`mcp_search` 工具本身、新增/导入/删除行与编辑弹窗「保存」及逐行保存状态的浏览器实测、设置写队列的单测（其 store 依赖在 Node 下无法加载）、以及用户 Include 的注释保留。
- 宿主更新可能带来兼容性变化；详细限制见 [设计说明](<docs/design-decisions.md>)。alpha 线并没有已知的失效——只是这次工作没有在它上面复跑。
